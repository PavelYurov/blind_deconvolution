В репозитории blind_deconvolution представлены исходные коды методов, здесь же скрипты запуска и инструменты визуализации для проведения экспериментов по подбору гиперпараметров (HPO) алгоритмов слепой деконволюции изображений.

1. Методология: Целевая функция и штрафы
Методы оптимизации (TPE и MCMC-FMP) осуществляют поиск гиперпараметров путем максимизации одной скалярной метрики. 
Внутри самого оптимизатора Парето-фронт не строится — метод ищет параметры, дающие наилучший результат в медианном случае по набору тестов.

1.1. Целевая функция
Для оценки набора параметров алгоритм прогоняется на N тестах. Тесты делятся на две группы: "размытые" (только смаз) и "шумные" (смаз и шум).
Итоговая метрика вычисляется как групповая медиана с равными весами групп абсолютного значения SSIM восстановленных изображений:
metric = 0.5*median(SSIM_blurred) + 0.5*median(SSIM_blurred&noisy)
Такой подход гарантирует, что оптимизатор не будет игнорировать простые (blurred) случаи даже при их малой доле в датасете.

1.2. Обоснование выбора метрики
В процессе подготовки экспериментов были протестированы альтернативные целевые функции. Выбранный вариант показал наилучшую сходимость оптимизаторов по следующим причинам:
1) Групповая медиана вместо обычной, потому что набор данных изначально несбалансирован (тестов со сложным шумом больше, чем чистых размытий). 
Если использовать обычную медиану по всем тестам, оптимизатор полностью игнорирует чистые случаи, скатываясь в экстремальное шумоподавление. 
Группировка с весами 0.5 и 0.5 заставляет алгоритм искать баланс.
2) Абсолютный SSIM, а не прирост (ΔSSIM), потому что изначально тестировавшаяся оптимизация прироста качества (ΔSSIM = SSIM_restored - SSIM_distorted) приводила к ложной сходимости: 
оптимизатору было проще улучшить крайне убитое изображение с SSIM 0.2 до 0.4 (Δ = 0.2), чем довести умеренно размытое изображение с 0.7 до идеальных 0.85 (Δ = 0.15).
Максимизация абсолютного качества заставляет алгоритм стремиться к наилучшему итоговому визуальному результату, независимо от стартовой точки.

1.3. Система штрафов
Для предотвращения вырожденных решений в целевую функцию введены штрафы.
1) Штраф за потерю дисперсии (штраф за "плоское" изображение): 
Если стандартное отклонение восстановленного изображения критически мало (std_restored < std_distorted/20)
значение SSIM_restored уменьшается на 0.4
(Порог 20 выбран экспериментально: менее агрессивен, чем 15, но более чувствителен, чем 30. Не влияет на нормальные результаты.)

2) Штраф за "дельта-ядро" (игнорирование смаза): Вычисляется нормализованная энтропия оцененного ядра PSF: E_norm = entropy(PSF)/log_2(N).
Если ядро вырождается в 2-5 значимых пикселя (E_norm < 0.3), то SSIM_restored уменьшается на 0.3.

После применения штрафов значение SSIM ограничивается нулем (clamping), чтобы не искажать медиану отрицательными выбросами.
(При двойном штрафе SSIM не уходит ниже нуля, сигнал остается значимым)

2. Анализ компромиссов: Построение 3D Парето-фронта
Парето-фронт строится постфактум (в онлайн-режиме после каждой итерации) по всем накопленным в процессе оптимизации точкам. Это аналитический инструмент, позволяющий детально изучить trade-off между сложностью искажений и качеством восстановления.
Скрипты создают два типа графиков: Стандартный Парето-фронт и Парето-фронт Noise Degradation (ND).

2.1. Оси Парето-фронтов
Каждая точка на графике соответствует одному тесту с конкретным набором гиперпараметров.

Ось (Сложность смаза): 
- Метрика (PSNR/SSIM) только смазанного изображения (без шума).
- Направление: Минимизируется. Чем ниже значение, тем сильнее смаз (сложнее случай). Нас интересует способность алгоритма работать со сложными случаями.

Ось Y (Два варианта построения):
- Вариант 1 (Стандартный фронт — Совокупная сложность):
  - Метрика: (PSNR/SSIM) полностью искаженного изображения (смаз и шум).
  - Направление: Минимизируется. Низкое значение означает, что изображение сильно искажено (много шума и сильный смаз). Если Y низкий, а X высокий — доминирует шум.
- Вариант 2 (Noise Degradation, ND — Изолированный вклад шума):
  - Метрика: Разность метрик смазанного (PSNR/SSIM) и полностью искаженного изображения (смазанного и зашумленного).
  - Направление: Максимизируется. Чем больше разница, тем сильнее шум ухудшил сцену. Это изолирует влияние шума от смаза.

- Ось Z (Качество восстановления - общая для обоих вариантов): Абсолютное значение метрики (PSNR/SSIM) восстановленного изображения.
Направление: Максимизируется. Чем больше значение метрики, тем лучше качество в сложном случае.

2.2. Правило доминирования
Множество Парето состоит из недоминируемых точек. Точка A доминирует точку B, если она не хуже по всем осям и строго лучше хотя бы по одной.
Для ND фронта:
- X_A <= X_B (справляется со смазом не хуже);
- Y_A >= Y_B (справляется с шумом не хуже);
- Z_A >= Z_B (качество восстановления не ниже);
- И хотя бы одно из неравенств строгое.
(для стандартного фронта аналогично, но Y_A <= Y_B)

2.3. RBF-интерполяция поверхности
Для визуализации гладкой поверхности, проходящей через точки фронта, применяется RBF-интерполяция с ядром thin-plate spline.
Особенности реализации:
- Поверхность проходит точно через точки фронта (минимальная энергия изгиба).
- Для устранения экстраполяционных артефактов ("пиков" в пустоте) применяется маскирование по евклидову расстоянию (cKDTree) с последующим гауссовым сглаживанием маски.
- Изолированные "заплатки" удаляются - воспроизводится только крупнейший связный компонент.

4. Запуск экспериментов (HPO)

4.1. Номенклатура файлов экспериментов
Имена запускаемых файлов строятся по следующему шаблону:
[ID]_[Алгоритм]_[Метод_Оптимизации]_[Итерации]iter_[Кол-во_Искаженных_Изображений]dist.py
Например: 17_lip_cv_tpe_100iter_75dist.py означает:
- 17: Порядковый номер эксперимента
- lip_cv: Оптимизируется алгоритм LIP_BD (CV).
- tpe: Используется оптимизатор TPE (вариант hmm_mcmc означает MCMC-FMP).
- 100iter: Оптимизатору выделен бюджет в 100 итераций поиска. 
- 75dist: В процессе вычисления целевой функции на каждой итерации оценивается 75 искаженных (distorted) изображений.
Примечание: В связи с ограниченными вычислительными мощностями (вычисления производились исключительно на CPU), размер набора данных для оптимизации был ограничен до 50 или 75 искаженных изображений для удержания времени одного HPO-эксперимента в разумных пределах.

Поскольку алгоритмы имеют множество гиперпараметров, все 48 скриптов разделены на 3 блока, чтобы оценить влияние размера пространства поиска на сходимость:
Блок 1 (Скрипты 1–16) — Полный перебор: Отсутствуют фиксированные параметры. Оптимизатор подбирает всё, включая выбор денойзеров и их силу. Широкий поиск.
Блок 2 (Скрипты 17–32) — Частичная фиксация: Настройки пайплайна шума зафиксированы. Оптимизируются только основные параметры алгоритма: веса регуляризаций и счетчики итераций.
Блок 3 (Скрипты 33–48) — Строгая фиксация: В поиске оставлен минимум гиперпараметров основного алгоритма для быстрой сходимости.

```
python plot_pareto_interactive_rotate.py pareto_17_lip_cv_tpe_100iter_75dist
```
Все отрисованные графики и HTML-страницы автоматически раскладываются по структурированным вложенным папкам (например, pareto_nd_plots/PSNR и т.д.) рядом с исходными JSON файлами.
